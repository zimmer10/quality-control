# Совместная разработка

## Как взять задачу

1. Убедиться, что зависимости задачи завершены.
2. Назначить себя исполнителем GitHub Issue.
3. Перевести задачу в `In Progress`.
4. Создать ветку вида `feature/R11-ocr-cache`.
5. Открыть Pull Request после выполнения критериев готовности.

Рекомендуемая область в roadmap не запрещает другому разработчику взять задачу.

## Pull Request

В PR обязательно указать:

- ID задачи;
- цель изменения;
- команду запуска;
- конфигурацию;
- тесты;
- полученные метрики;
- созданные артефакты;
- известные ограничения.

Второй разработчик проверяет PR до слияния.

## Общие контракты

`folds.parquet` создаётся один раз и используется всеми ветками. Самостоятельно пересчитывать folds нельзя.

Каждая OOF-таблица содержит как минимум:

```text
id
category
fold
group_id
true_label
```

Требования:

- одна строка на один `id`;
- соединение таблиц выполняется по `id`;
- `fold`, `group_id` и `true_label` совпадают между OOF-таблицами;
- конфигурация и commit эксперимента сохраняются в отчёте;
- результаты обучаемой модели для следующего уровня должны быть OOF.

## Definition of Done

- [ ] Код воспроизводимо запускается.
- [ ] Ключевая логика покрыта тестами.
- [ ] Формат выходных артефактов проверен.
- [ ] Метрики и команда запуска записаны в отчёт.
- [ ] Нет установленной утечки данных.
- [ ] Документация обновлена.
- [ ] PR проверен вторым разработчиком.

## Git и большие файлы

В Git не добавляются:

- исходные данные и изображения;
- OCR cache и embeddings;
- OOF-предсказания;
- веса моделей и LoRA-адаптеры;
- retrieval-индексы;
- Docker-архивы.
