# E-CUP «Контроль качества»: условия задачи

## 1. Задача

Необходимо разработать классификатор товаров двух категорий:

- `БАД`;
- `Легковоспламеняющиеся`.

Для каждого товара решение должно использовать название, описание и от 1 до 5 изображений, а затем:

1. Определить итоговый бинарный вердикт.
2. Сформировать объяснение принятого решения.

Категория товара известна во входных данных. Правила классификации для двух категорий различаются.

## 2. Входные данные

### 2.1. Структура `data.csv`

| Поле | Описание |
|---|---|
| `id` | Идентификатор товара |
| `name` | Название товара |
| `description` | Описание товара |
| `category` | Категория товара: `БАД` или `Легковоспламеняющиеся` |
| `label` | Целевая бинарная метка качества: `1` — качественный товар, `0` — некачественный товар |

Для каждого товара доступно от 1 до 5 изображений. Путь к папке с изображениями определяется на основе пути к входному CSV-файлу, как в baseline-решении.

На закрытом тесте будут товары, отличающиеся от обучающих. Поле `label` в тестовых данных недоступно.

## 3. Правила классификации

### 3.1. Биологически активные добавки

Товар является БАД, если:

- в описании или на изображении есть прямое указание, что товар является биологически активной добавкой;
- присутствует маркировка `БАД` или `dietary supplement`.

Товар не является БАД, если выполняется хотя бы одно из условий:

- товар является спортивным питанием: аминокислоты, BCAA, L-карнитин, протеин либо иной товар с прямым указанием на принадлежность к спортивному питанию;
- в описании явно указано, что товар не является биологически активной добавкой;
- в описании и на изображениях отсутствуют маркировки `БАД` и `dietary supplement`.

### 3.2. Легковоспламеняющиеся товары

Товар является легковоспламеняющимся, если выполняется хотя бы одно из условий:

- товар является самостоятельным источником воспламенения, основное назначение которого — создание или поддержание открытого огня, например спички или зажигалка;
- товар содержит горючее вещество, легковоспламеняющееся вещество или горючий газ;
- в комплект товара входит легковоспламеняющийся товар.

Товар не является легковоспламеняющимся, если выполняется хотя бы одно из условий:

- товар не содержит источника воспламенения или горючего вещества;
- товар является устройством для использования с огнём или горючими веществами, но сам не содержит их, например мангал, гриль или газовая плита;
- легковоспламеняющимся является содержимое, но это содержимое отсутствует;
- источник воспламенения встроен в изделие;
- потенциально горючий материал является только компонентом другого изделия и не представляет собой самостоятельный товар, например активированный уголь в фильтре или уголь для рисования;
- легковоспламеняющийся предмет не входит в комплект.

## 4. Интерфейс запуска решения

Решение запускается как автономное контейнерное приложение и получает именованные аргументы:

```text
--test_data_path, -i  путь к CSV-файлу с тестовыми товарами
--output-path, -o     путь к выходному CSV-файлу
```

Пример:

```bash
python -u run.py --test_data_path test.csv --output-path submit.csv
```

Во время проверки доступ в интернет отсутствует. Все библиотеки, конфигурации и дополнительные файлы должны быть заранее включены в Docker-образ или архив решения. Решение должно сформировать ответ для каждого входного товара без исключения.

## 5. Формат результата

Решение должно сохранить CSV-файл с двумя столбцами:

| Столбец | Содержимое |
|---|---|
| `id` | Идентификатор входного товара |
| `result` | Объяснение и итоговый вердикт |

Значение `result` должно соответствовать строгому формату:

```text
<комментарий><вердикт>
```

Требования:

- закрывающие теги не используются;
- вердикт может быть только `<бан>` или `<не бан>`;
- комментарий должен содержать от 50 до 300 символов;
- объяснение и вердикт должны присутствовать для каждого товара.

Пример:

```text
На упаковке присутствует прямое указание «БАД», поэтому товар относится к биологически активным добавкам. <бан>
```

## 6. Метрика

Основная метрика — среднее значение F1 по двум категориям:

```text
F1_BAD
F1_FLAMMABLE

competition_score = (F1_BAD + F1_FLAMMABLE) / 2
```

Для расчёта используется `sklearn.metrics.f1_score`.

Закрытый тест приблизительно разделён на:

- 30% — public leaderboard, около 1600 товаров;
- 70% — private leaderboard, около 3800 товаров.

## 7. Ресурсы и ограничения запуска

Доступные ресурсы:

```text
CPU:  20 ядер
RAM:  100 GB
GPU:  NVIDIA Tesla H100, 80 GB
```

Ограничения по времени:

| Набор | Лимит |
|---|---:|
| Check, 10 отладочных примеров | 3 минуты |
| Public test | 20 минут |
| Private test | 40 минут |

Если решение падает, превышает лимит ресурсов или времени либо создаёт некорректный файл, метрика не рассчитывается.

## 8. Упаковка решения

Решение отправляется в виде архива. В архиве должны находиться код, конфигурации и необходимые веса, которые не предоставляются средой соревнования.

Ограничения:

```text
архив решения: не более 5 GB
Docker-образ в сжатом виде: не более 15 GB
```

В корне архива обязателен файл `metadata.json`:

```json
{
  "image": "odsai/ecup26-quality-baseline:1.0",
  "entry_point": "python -u run.py"
}
```

Можно использовать baseline-образ либо собственный Docker-образ с заранее установленными зависимостями. Для проверки собственный образ должен быть доступен проверяющей системе через Docker Hub и указан в `metadata.json`.

## 9. Ограничения на модели и обучающие данные

Разрешены малые модели размером до 4B с открытой лицензией и легальным статусом.

Допускается:

- использовать модели из предоставленного организаторами списка;
- включить другую открытую модель в архив, если весь архив укладывается в лимит 5 GB;
- обучать собственные LoRA-адаптеры под задачу.

Не допускается:

- использовать модели с закрытой или неподходящей лицензией;
- использовать запрещённые `qwythos-like` модели;
- обучать решение или LoRA на объяснениях, сгенерированных закрытой проприетарной моделью;
- использовать нелегальные или непрозрачно полученные обучающие данные.

Весь pipeline обучения, включая подготовку объяснений и структурированной разметки, должен соответствовать требованиям открытости и легальности.

    _SHARED_MODELS_DIR,

Для локальной подготовки копии модели можно использовать `snapshot_download` из `huggingface_hub`.

## 10. Критерии технически валидного решения

Решение считается технически валидным, если оно:

1. Автономно запускается без интернета на закрытых данных.
2. Укладывается в ограничения по времени, CPU, RAM и GPU.
3. Не превышает ограничения архива и Docker-образа.
4. Создаёт CSV-файл с колонками `id` и `result`.
5. Возвращает ровно один корректно оформленный результат для каждого товара.
6. Использует только разрешённые модели, веса и обучающие данные.
